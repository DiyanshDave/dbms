Part A: SQL Concepts

1) Define: (1) Primary key (2) Foreign key (3) Unique Key (4) Not null (5) Commit (6) Candidate key (7) Rollback.

  • Primary key: A column (or set of columns) that uniquely identifies each row of a table. It cannot contain NULL or duplicate values and a table has only one primary key. Example: rollno INT PRIMARY KEY.
  • Foreign key: A column in one table that refers to the primary key (or unique key) of another table. It enforces referential integrity, so the value must exist in the parent table or be NULL. Example: dept_id REFERENCES Dept(dept_id).
  • Unique key: A constraint that ensures all values in a column are different. Unlike a primary key it allows NULL (in most DBMS) and a table can have many unique keys. Example: email VARCHAR(50) UNIQUE.
  • Not null: A constraint that does not allow a column to hold NULL; a value must always be supplied. Example: name VARCHAR(30) NOT NULL.
  • Commit: A TCL command that permanently saves all changes made by the current transaction to the database and makes them visible to other users.
  • Candidate key: A minimal set of attributes that can uniquely identify a row. A table may have several candidate keys; one is chosen as the primary key and the rest are alternate keys. Example: in Student, both rollno and email may be candidate keys.
  • Rollback: A TCL command that undoes all changes made since the last COMMIT (or up to a SAVEPOINT), restoring the database to its earlier consistent state.

2) Define: (1) Weak entity (2) Data Dictionary (3) Substring( ) (4) Dual (5) Alter (6) Truncate (7) Drop.

  • Weak entity: An entity that does not have enough attributes to form a primary key of its own and depends on a strong (owner) entity through an identifying relationship. It has a partial key (discriminator) and is shown by a double rectangle in the ER diagram. Example: Dependent of an Employee.
  • Data dictionary: A set of system-maintained tables that store metadata (data about data): table names, columns, data types, constraints, users, privileges, indexes and views. Example in Oracle: USER_TABLES, USER_TAB_COLUMNS.
  • Substring( ): A string function that extracts part of a string from a given starting position for a given length. Syntax: SUBSTR(string, start, length). Example: SUBSTR('DATABASE',1,4) gives DATA.
  • Dual: A one-row, one-column dummy table in Oracle, used to evaluate expressions or functions that do not need a real table. Example: SELECT SYSDATE FROM DUAL;
  • Alter: A DDL command that changes the structure of an existing table: add, modify or drop columns or constraints. Example: ALTER TABLE Emp ADD phone VARCHAR(15);
  • Truncate: A DDL command that removes all rows from a table quickly, keeping its structure. It cannot be rolled back and has no WHERE clause. Example: TRUNCATE TABLE Emp;
  • Drop: A DDL command that deletes the whole table (structure, data, indexes and constraints) permanently from the database. Example: DROP TABLE Emp;

3) What is ON DELETE CASCADE in SQL? Explain clearly with example.

ON DELETE CASCADE is an option of a FOREIGN KEY constraint. When a row in the parent table is deleted, all the matching rows in the child table that refer to it through the foreign key are automatically deleted. It keeps referential integrity without deleting the child rows manually. Without it, deleting a parent row that is still referenced gives an error.

CREATE TABLE Dept (
  dept_id   INT PRIMARY KEY,
  dept_name VARCHAR(20)
);
CREATE TABLE Emp (
  emp_id   INT PRIMARY KEY,
  emp_name VARCHAR(20),
  dept_id  INT,
  FOREIGN KEY (dept_id) REFERENCES Dept(dept_id)
           ON DELETE CASCADE
);
Dept (parent)Emp (child)

DELETE FROM Dept WHERE dept_id = 10;

Result: Dept row 10 is deleted and Emp rows Ravi and Meena (dept_id = 10) are deleted automatically. Only John remains.

Related options: ON DELETE SET NULL (child foreign key becomes NULL) and ON DELETE RESTRICT / NO ACTION (delete not allowed while child rows exist).

5. Cross Join (Cartesian product)

Pairs every row of the first table with every row of the second, so 3 x 3 = 9 rows, with no join condition.

A table is joined with itself using aliases, e.g., to list employees with their managers.

SELECT e.ename AS employee, m.ename AS manager
FROM Emp e JOIN Emp m ON e.mgr = m.eid;

5) Explain natural join operation with example.

A natural join joins two tables automatically on all columns with the same name and compatible data type. No ON condition is written, and the common column appears only once in the result. 8) Explain any two string functions in SQL.

1. UPPER( )

Converts all characters of a string to uppercase. Syntax: UPPER(string)

SELECT UPPER('database management') FROM DUAL;
-- Result: DATABASE MANAGEMENT
SELECT UPPER(sname) FROM Supplier;

2. SUBSTR( )

Extracts a part of a string. Syntax: SUBSTR(string, start_position, length). The first position is 1; a negative start counts from the end (Oracle); if length is omitted, the rest of the string is returned.

SELECT SUBSTR('DATABASE', 1, 4) FROM DUAL;   -- DATA
SELECT SUBSTR('DATABASE', 5)    FROM DUAL;   -- BASE
SELECT SUBSTR('DATABASE', -4, 2) FROM DUAL;  -- BA

9) Explain any two aggregate functions of SQL.

Aggregate functions work on a set of rows and return a single value. They ignore NULL values (except COUNT(*)) and are often used with GROUP BY. Other aggregate functions: COUNT, MAX, MIN.

1. SUM( )

Returns the total of the values of a numeric column. Syntax: SUM([DISTINCT] column)

SELECT SUM(sal) FROM Emp;   -- 50000 (NULL ignored)

2. AVG( )

Returns the average of the non-NULL values of a numeric column. Syntax: AVG(column)

SELECT AVG(sal) FROM Emp;   -- 25000 (50000 / 2 values)

With grouping: SELECT deptno, SUM(sal), AVG(sal) FROM Emp GROUP BY deptno;

10) What is View? Give the advantages of View.

A view is a virtual table based on the result of a stored SELECT query. It does not store data itself; it displays data from one or more base tables and is recomputed every time it is used.

CREATE VIEW emp_dept AS
SELECT e.ename, e.sal, d.dname
FROM Emp e JOIN Dept d ON e.deptno = d.deptno
WHERE e.sal > 3000;

SELECT * FROM emp_dept;
DROP VIEW emp_dept;

Advantages of views

  • Security: hides sensitive columns/rows; users see only permitted data.
  • Simplicity: hides complex joins and queries behind a simple name.
  • Logical data independence: the base table structure can change without changing applications.
  • Customised presentation: different users get different views of the same data.
  • Consistency and reuse: one query definition is reused everywhere; no data duplication, so no extra storage.

Limitation: updates through views are restricted for views with joins, GROUP BY, DISTINCT or aggregates.

11) Explain what is NULL?

NULL is a special marker that represents a value that is missing, unknown or not applicable. It is not the same as zero or an empty string.

  • A column can hold NULL unless it has a NOT NULL or PRIMARY KEY constraint.
  • Comparison with NULL using =, <> gives UNKNOWN, so use IS NULL or IS NOT NULL.
  • Any arithmetic with NULL gives NULL (e.g., 100 + NULL = NULL).
  • Aggregate functions (SUM, AVG, COUNT(column)) ignore NULLs.
  • Logic is three-valued: TRUE, FALSE, UNKNOWN. NULL = NULL is UNKNOWN, not TRUE.
  • Functions to handle NULL: NVL(x, 0) in Oracle, COALESCE(x, 0).
SELECT ename FROM Emp WHERE comm IS NULL;
SELECT ename, sal + NVL(comm, 0) FROM Emp;

(iii) Explain commit command.

COMMIT is a TCL command that ends the current transaction and permanently saves all its DML changes (INSERT, UPDATE, DELETE) to the database, makes them visible to other users, and releases the locks. After COMMIT, the changes cannot be rolled back. DDL statements commit automatically.

DELETE FROM Supplier WHERE status = 40;
COMMIT;   -- change is now permanent

(iv) Explain Cursor in PL/SQL.

A cursor is a pointer to a private memory area (context area) created by Oracle to hold the rows returned by a SQL statement, which lets PL/SQL process a multi-row result one row at a time. Implicit cursors are created automatically for INSERT, UPDATE, DELETE and single-row SELECT. Explicit cursors are defined by the programmer and handled in four steps: DECLARE, OPEN, FETCH, CLOSE. (Detailed answer in PL/SQL Q3.)

DECLARE
  CURSOR c1 IS SELECT sname FROM Supplier;
  v_name Supplier.sname%TYPE;
BEGIN
  OPEN c1;
  LOOP
    FETCH c1 INTO v_name;
    EXIT WHEN c1%NOTFOUND;
    DBMS_OUTPUT.PUT_LINE(v_name);
  END LOOP;
  CLOSE c1;
END;

Part B: PL/SQL Concepts

1) Explain the advantages of PL/SQL.

PL/SQL (Procedural Language extension to SQL) is Oracle's block-structured language that combines SQL with procedural features such as variables, conditions, loops and exception handling. Its main advantages are:

  • Tight integration with SQL: SQL statements and data types can be used directly inside the program.
  • Procedural constructs: IF-ELSE, CASE, LOOP, WHILE and FOR give full programming control, which SQL alone lacks.
  • Better performance: a whole block is sent to the server in one call, which reduces network traffic and execution time.
  • Modularity and reusability: programs are divided into blocks, procedures, functions and packages that are stored and reused.
  • Exception handling: run-time errors are trapped and handled cleanly in the EXCEPTION section.
  • Portability: PL/SQL code runs on any platform where Oracle runs.
  • Security: access is given to stored procedures without exposing the underlying tables.
  • Supports triggers, cursors and OOP features such as objects and collections.

Structure of a PL/SQL block

DECLARE      -- optional: variables, cursors
  v_name emp.ename%TYPE;
BEGIN        -- mandatory: executable statements
  SELECT ename INTO v_name FROM emp WHERE empno = 7839;
  DBMS_OUTPUT.PUT_LINE('Name: ' || v_name);
EXCEPTION    -- optional: error handling
  WHEN NO_DATA_FOUND THEN
    DBMS_OUTPUT.PUT_LINE('No such employee');
END;
/

2) Explain commit and rollback command.

Both are TCL (Transaction Control Language) commands that manage the changes made by DML statements.

COMMITROLLBACK
PurposePermanently saves all changes of the current transactionUndoes all changes since last COMMIT (or SAVEPOINT)
EffectChanges become visible to others; locks releasedDatabase returns to the previous consistent state
SyntaxCOMMIT;ROLLBACK; or ROLLBACK TO savepoint_name;
After useCannot be undoneChanges are lost
INSERT INTO Dept VALUES (50, 'Audit', 'Pune');
SAVEPOINT sp1;
UPDATE Emp SET sal = sal + 1000 WHERE deptno = 10;
ROLLBACK TO sp1;     -- undoes only the UPDATE
COMMIT;              -- saves the INSERT permanently
  • SAVEPOINT marks a point within a transaction to which a partial rollback can be done.
  • DDL commands (CREATE, ALTER, DROP) and normal exit from SQL*Plus cause an implicit commit.
  • On a system failure or abnormal termination, uncommitted work is automatically rolled back.
  • Together they ensure the Atomicity and Durability of transactions.

3) Write note on Cursor and its types.

A cursor is a pointer to a private SQL work area (context area) in memory where Oracle stores the result of a SQL statement. It allows PL/SQL to process the rows of a query result one by one. There are two types:

1. Implicit cursor

Created automatically by Oracle for every INSERT, UPDATE, DELETE and SELECT ... INTO statement. The programmer cannot control it, but its status is available through the cursor named SQL.

BEGIN
  UPDATE emp SET sal = sal + 500 WHERE deptno = 10;
  IF SQL%FOUND THEN
    DBMS_OUTPUT.PUT_LINE(SQL%ROWCOUNT || ' rows updated');
  END IF;
END;
/

2. Explicit cursor

Declared and controlled by the programmer for queries that return more than one row. Four steps: DECLARE (define the cursor with its query), OPEN (execute query), FETCH (read one row into variables) and CLOSE (release memory).

DECLARE
  CURSOR c_emp IS SELECT ename, sal FROM emp WHERE deptno = 10;
  v_name emp.ename%TYPE;
  v_sal  emp.sal%TYPE;
BEGIN
  OPEN c_emp;
  LOOP
    FETCH c_emp INTO v_name, v_sal;
    EXIT WHEN c_emp%NOTFOUND;
    DBMS_OUTPUT.PUT_LINE(v_name || ' ' || v_sal);
  END LOOP;
  CLOSE c_emp;
END;
/

Cursor attributes

AttributeMeaning
%FOUNDTRUE if the last fetch/DML affected at least one row
%NOTFOUNDTRUE if the last fetch returned no row
%ISOPENTRUE if the cursor is open (always FALSE for implicit)
%ROWCOUNTNumber of rows fetched or affected so far

Other forms: cursor FOR loop (opens, fetches and closes automatically), parameterised cursor, and REF cursor (dynamic cursor).

FOR rec IN c_emp LOOP
  DBMS_OUTPUT.PUT_LINE(rec.ename);
END LOOP;

4) Write short note on database triggers in PL/SQL.

A database trigger is a stored PL/SQL block that is executed automatically (fired) by the database when a specified event occurs on a table or view: INSERT, UPDATE or DELETE. It is used to enforce complex business rules, maintain audit trails and keep data consistent.

Syntax

CREATE [OR REPLACE] TRIGGER trigger_name
{BEFORE | AFTER | INSTEAD OF}
{INSERT | UPDATE [OF column] | DELETE} ON table_name
[FOR EACH ROW] [WHEN (condition)]
BEGIN
  -- trigger body
END;
/

Types of triggers

  • Timing: BEFORE (fires before the event) and AFTER (fires after the event).
  • Level: Row-level (FOR EACH ROW, fires once per affected row, can use :OLD and :NEW) and statement-level (fires once per statement).
  • Event: INSERT, UPDATE, DELETE triggers.
  • INSTEAD OF triggers on views; also system and DDL triggers (LOGON, CREATE).

:OLD holds the old row values (UPDATE/DELETE) and :NEW holds the new row values (INSERT/UPDATE).

Example 1: validation (BEFORE trigger)

CREATE OR REPLACE TRIGGER trg_check_sal
BEFORE INSERT OR UPDATE OF sal ON emp
FOR EACH ROW
BEGIN
  IF :NEW.sal < 0 THEN
    RAISE_APPLICATION_ERROR(-20001, 'Salary cannot be negative');
  END IF;
END;
/

Example 2: audit (AFTER trigger)

CREATE OR REPLACE TRIGGER trg_emp_audit
AFTER DELETE ON emp
FOR EACH ROW
BEGIN
  INSERT INTO emp_audit VALUES (:OLD.empno, :OLD.ename, SYSDATE);
END;
/

Advantages: automatic enforcement of rules, auditing, data integrity, less application code. Disadvantages: hidden logic, harder debugging, can slow down DML. Triggers are removed with DROP TRIGGER name; and switched with ALTER TRIGGER name ENABLE/DISABLE;
